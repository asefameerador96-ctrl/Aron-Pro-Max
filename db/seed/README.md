# Seed data (development and test only; never production)

Three classes of data, three homes (audit AUD-DA-04):

| Class | Examples | Where it lives | Reaches |
|---|---|---|---|
| System reference | code-list items (V0027), config defaults (V0006, V0012), role grants and limits, geo classes, event catalogue | `db/migrations` | every environment |
| Synthetic test data | the Mirpur test fixture (CI and backend tests), the Gulshan/Banani dev geography (Azure dev only), test accounts, outlets, the dev device, dev config overrides | `db/seed` (this folder) | local, CI and dev only |
| Customer master | AKTCL's hierarchy, people, routes, outlets, prices | admin import and admin pages | QA, staging, production |

| File | Content |
|---|---|
| `sku_catalog.csv` | the real Aron product catalogue: 4 categories, 6 segments, 17 brands, 30 variants, 42 SKUs, five price types (outlet, C&C, distributor, reporting, NTO) and pack size/type |
| `01_geography_people.sql` | wing W-CEN > division D-DHK > territory T-DHK-N > house H-MIR > zone Z-MIR, three clusters, the SR routes MIR-SR-D (Daily, mask 127), MIR-SR-3F (Sun, Tue, Thu, mask 42) and MIR-SR-2F (Mon, Thu, mask 36), test accounts and their scope |
| `02_products.sql` | generated by `gen_products.py` from the CSV (prices in milli-taka, valid from 2026-01-01). Regenerate with `python3 db/seed/gen_products.py` from the repo root; never edit by hand |
| `03_outlets_and_plans.sql` | 60 outlets, 20 per route, fixed pins on a ~70 m grid around 23.8069 N, 90.3687 E (Mirpur 10, Dhaka); placement and location history; the zone's sales plan (SKUs with a non-zero outlet price) |
| `05_dev_device.sql` | an active dev phone (`device_uuid` 00000000-0000-4000-8000-000000000001, placeholder key) bound to `sr1001` with `bind_ordinal` 0 |
| `04_dev_config_and_codes.sql` | a new config version (next number, found again by its summary): the dev overrides of docs/24 s9.4 (`require_enrolled` false, `lockdown_level` dev, `require_integrity` false) and a test holiday |
| `06_dev_gulshan_banani.sql` | **Azure dev only** (no-op when 04's config version exists, i.e. in CI, backend tests and a local load; the dev deploy skips `04_*`): house H-GUL, zones Z-GUL and Z-BAN, three Friday-aware 2F routes GUL-SR-2 (Sat, Tue), GUL-SR-1 (Sun, Wed), BAN-SR-11 (Mon, Thu), 60 outlets with every channel plus the owner's three test outlets on GUL-SR-1 (D-NIGHT-SEED-OUTLETS-01), sales plans, route x SKU targets and holidays for the three months from the seed's today (D-DB-SEED-ROLLING-01); moves sr1001 (and amo1001's scope) there and sets MIR-SR-* inactive (D-SEED-02). Map: `docs/evidence/seed-gulshan-banani.md` |
| `07_admin_module_grants.sql` | the seeded (pilot) ADMIN accounts hold every one of the 15 modules at `w` (D-ROLES-02; the V0089 CHECK and the contract's AdminModule list), only once `app.user_module_grant` exists and only while the account has no grant row, so a narrowed grant stays narrowed; idempotent. From backend-authz (3b7747b5), owned by db since 2026-10-22; seed 01 already grants admin1001, this covers every pilot admin |

Test accounts (all `pilot`, home zone Z-MIR): `sr1001` (SR, primary on the three routes), `amo1001` (AMO, zone),
`tso1001` (TSO, territory T-DHK-N), `dmo1001` (DMO, division), `admin1001`, `superadmin1001`, `support1001` (national).
**No passwords are committed**: with `ARON_SEED_PASSWORD` set, the loader stores its Argon2id hash on every test
account; without it they have no password until the admin credential reset. `must_change_password` is false.

Load into a migrated database (every file is idempotent; a second run changes nothing):

```
ARON_SEED_DB_URL='jdbc:postgresql://HOST:5432/DB?user=USER&password=...' ./gradlew :db:seed
# or: for f in db/seed/0*.sql; do psql "$PGURL" -v ON_ERROR_STOP=1 -f "$f"; done
```

SKU codes with a space in the catalogue are stored with `_` (contract pattern); `short_name` and `external_ref` keep
the original (`docs/requests/db-sku-code-spaces.md`).
