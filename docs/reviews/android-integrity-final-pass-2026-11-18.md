## gate-cannot-be-bypassed verdict=pass
SUMMARY: PASS for the developer-options gate lens. Read-only review of origin/lane/android-integrity at bfa5ead5 against 29e8d86f3; nothing was built or run.

(a) Entry points. The three apps have exactly four activities: SR MainActivity (exported launcher), SR OutletMapActivity (not exported), AMO MainActivity, TSO MainActivity. All four call setGatedContent in onCreate; there is no raw setContent/setContentView in shipped code and EveryActivityIsGatedTest enforces it. No deep-link, share-target or widget filters exist. Other components: BreadcrumbReceiver, InstallStatusReceiver and AronMessagingService are not exported; the only exported non-activity is the empty AronDeviceAdminReceiver (BIND_DEVICE_ADMIN, no provisioning filter). The gate is built in Application.onCreate of all three apps before any activity or worker. It is re-read on first composition (so cold start, recents restore and notification taps hit it), on every resume, on window focus, and by a ContentObserver on the three settings while the activity is started; the gated content is not composed at all while blocked, and the recents thumbnail is hidden.
Writes. ActionGate.requireOpen() is the first statement of: recordAttendance, recordStock, recordVisitOpen, recordSale, recordNumberedSale, recordVisitClose, recordDueCollection, recordAmo, recordVisitSkip, recordContentView, recordSurveyResponse, recordDaySubmit, recordCheckOut, recordClusterCreate, recordOutletRequest(s), resolveTask, and TsoOutbox.enqueueAll (the one TSO outbox entry; TicketsHost goes through it). It runs before the check-in gate everywhere both exist (test theDeveloperOptionsGateComesBeforeTheCheckInGate). Deliberately not gated: recordBreadcrumb, recordMediaMeta, recordDeviceStatus, addPhoneMark, and the sync upload. Not covered at the write layer: TSO direct online POSTs (final submit, change password) - a low.

(b) Detected: development_settings_enabled, adb_enabled, adb_wifi_enabled. Mock-app selection is not a gate flag; it is in the spoof layer. Bypass routes are listed in the lows; the docs do not claim 'impossible'.

(c) Honest users. The gate screen shows Bangla then English: why, which flag is on, numbered steps including the hidden-menu case, 'data is safe', Check again, Open Settings, Sync now. It needs no network. A failed settings read fails OPEN (stated in code). A refused write throws GateClosedException, a CancellationException: flows rethrow it and reset busy state in finally; resumeDay settles in a NonCancellable finally; no crash path found. Login/OTP FLAG_SECURE is kept through the shared SecureHolders reference count.

(d) Queued data. The gate touches no session, database, outbox or WorkManager state. Background sync is allowed while gated and the screen says so; 'Sync now' requests an upload. Records are kept and upload with or without the setting being turned off.

(e) TSO is wired identically (Application install, setGatedContent, TsoOutbox gate, TsoOutboxGateTest).

(f) MDM. The policy applier, blocking engine, hard-end alarm, kiosk/lock-task, boot receiver, provisioning activities, self-installer, MdmCommandShell and DeviceOwnerPolicy are deleted. Remaining DevicePolicyManager use is read-only isDeviceOwnerApp for status, and DeviceOwnerRelease, which only UNDOES old state (unsuspend, clear lock task/restrictions, clearDeviceOwnerApp) once. Removing the DeviceOwnerPolicy block from SrDay/AmoDay.commitAttendance removed only the check-in/check-out hooks that started and released app blocking; the attendance write, breadcrumb window, integrity evidence and sync request are unchanged.

Not verified: no build, unit test or device run; behaviour on real OEM phones (whether disabling Developer options clears the mock app, whether any pilot ROM ships with the setting on, ContentObserver delivery in split screen); the Compose timing of the gate on a 2 GB phone; the lab-grant server side, migrations V0205..V0208, contract 1.21.0, Room 10->11 and the web card were not re-read in this lens (covered by earlier rounds and other lenses); the Loyalty train is not merged yet, so its new writers are unchecked.

## spoof-layers-and-server verdict=pass
SUMMARY: Pass: no blocking defect found in the anti-spoofing layers or the server side; nine lows, none of which blocks a sale. Nothing was built or run; this is a code read of git diff 29e8d86f3..bfa5ead5.

Phone:
- All spoof checks run only at the moment of a fix. No continuous GPS or sensor listener was added; the only new location read is a passive last-known network location, and the slow facts (packages, AppOps, root hints, /proc/self/maps) are cached for 10 minutes and read off the main thread.
- Only three codes refuse the geo-validated action: mock_flag, mock_app_selected and test_provider. Everything else (no satellites, no GNSS status, stale fix, clock mismatch, jump, speed, provider disagreement, root, emulator, hook, fake-GPS app installed) only rides the record.
- An honest rep indoors or on a phone without GNSS status is not refused. A failed check leaves signals unknown (null), never "clean", and never blocks the fix. No network call is in the path.
- The Developer-options gate is the first line of every operational write in CaptureRepository and TsoOutbox, ahead of the check-in gate. Uploads of queued records do not consult it.

Wire:
- GeoFix.signals and DeviceStatusReport.integrity_events are optional and additive; an old phone sends neither and is still accepted. The phone caps signals at 16 known codes and the server enforces 16.

Server:
- Ingest checks the shape of both members. The risk evaluator reads stored evidence defensively, runs each source and each store in its own savepoint, and evaluates each date separately, so one malformed row cannot stop the others.
- Hits are per phone and per user, shared phones get distinct rows, repeated events are deduplicated by instant and flags, and event dates are taken in Asia/Dhaka.
- The server geofence re-check is unchanged; a hard code sets is_mock, so such a fix is never geo-valid.

Migrations V0205..V0208:
- All four are new files; no shipped migration is edited.
- V0205 adds one nullable column with no default to the partitioned geo_fix table: metadata only, no rewrite, lock_timeout 5 s, safe with existing rows.
- V0206 and V0207 create the small lab-exemption table with comments and call the role-grant function. V0208 gives api_rw DELETE on that table only, following the existing per-table pattern.

Lab exemption:
- PUT and DELETE are limited to ADMIN and SUPERADMIN (not SUPPORT), reach-checked (404 outside reach or for a revoked phone) and audited without the token.
- The grant is ECDSA-signed once, bound to the device UUID and API host, capped at 14 days, and delivered only in a full day bundle.

Wording: no string or doc claims spoofing is impossible; the gate and refusal texts are plain and honest.

Fix before landing if possible: the stale "1.19.0" / "(V0204)" text inside the migrations (they cannot be edited once shipped), and the DEVICE_INTEGRITY_FAIL evidence overwrite. Deploy the backend and migrations before any APK from this branch.

LOWS:
- Shared risk row, evidence overwritten (most worth fixing). Phone-signal hits for root_hint / emulator / hook_framework are stored as DEVICE_INTEGRITY_FAIL with subject 'device' + device UUID + date: the same unique key the Play Integrity row (DeviceService.kt ~line 326) and the ingest gate rows (IngestService.kt flagDevice / insertSignatureFlag) already use.
