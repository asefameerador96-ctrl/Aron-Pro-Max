Reviewed 2026-11-18 by the lead (Opus pass, two lenses). Verdict: PASS, lows only. The two CI runs the lane cites were read through the public API; GitHub Actions could not be run by the reviewers.

## workflow-gate-strength verdict=pass
SUMMARY: I found nothing blocking in lane/ci-web-e2e (delta f5bfee39..1e4eb3bb). The old 'Web (lint, types, tests, build, e2e)' job is now three jobs. 'web' (renamed 'Web (lint, types, tests, build)') keeps every earlier step, adds the e2e count and uploads the build as `web-build-<run_id>`. 'web-e2e' is a 5-shard matrix with fail-fast off and the same 30-minute limit, running Playwright --shard. 'web-check' carries the unchanged required name, has `if: always()` and `needs: [changes, web, web-e2e]`. web-check passes only in two cases: (a) the changes job succeeded, web changed, the build job and the whole matrix were 'success', all 5 reports were found, and the reports add up to the listed total with 0 failed and 0 skipped; or (b) web did not change and both jobs were skipped. Skipped, cancelled or failed results all exit 1 when web changed. The filter, retries (config untouched, already 1), timeouts and action SHAs are unchanged. The only added permission is `actions: read`, which run-scoped `gh run download` needs, and no new secrets are exposed. tools/github-governance.ps1 is unchanged. The LiteMapScreen default stays Dispatchers.IO and no production caller is affected. Cited runs, checked through the public API and the web-check log: 44227267913 (push, 49005d3) and 44231175158 (workflow_dispatch, 1e4eb3b) both concluded success, each with 'Web (lint, types, tests, build)', five 'Web e2e (shard n of 5)' jobs and the aggregator all green. The aggregator log for 44231175158 shows 78, 72, 76, 72 and 74 passed, '372 of 372 tests', 0 flaky, failed or skipped. Not checked: I could not run Actions, so re-run-failed-jobs and artifact overwrite across attempts were not exercised; I did not run the Android unit test or the e2e locally; I did not compare against a pre-lane run to confirm 372 was the old total. The lows are minor: the count step hides its own exit status (it still fails closed downstream), a comment overstates the flaky rule, 1-day build retention makes late partial re-runs fail closed, and a non-web run now reports success instead of skipped, which branch protection and deploy treat the same.

LOWS:
- ci.yml:677 (count step): `echo "total=$(bash scripts/ci.sh count-e2e)"` hides the exit status of count-e2e, because the substitution's failure does not fail the echo, even though ci.sh uses pipefail. If --list fails outright, the output is empty and web-check's int('') crashes, so the check fails closed. If a spec file fails to load but the JSON is still printed, the total could come out short. That is still not a false pass: Playwright treats a load error as a run failure, so the shards fail and so does web-check (SHARDS_RESULT != success). Suggest `total=$(...) || exit 1; [ "$total" -gt 0 ]` so the count step fails by itself.
- ci.yml:775 (web-check header comment) says it passes only 'with 0 failed and 0 flaky', but the Python at ci.yml:~826 only warns on flaky. This matches the old behaviour (the old flaky step only warned, AUD-TP-6), so nothing is loosened; the comment is wrong.
- ci.yml:688: the web-build artifact keeps retention-days: 1. A 'Re-run failed jobs' on a shard more than 24 h later cannot download the build. The successful web job is not re-run, so the shard fails and web-check fails. This fails closed; it is a usability cost only, and 'Re-run all jobs' recovers.
- Changes-area filter equivalence: the web/e2e trigger is unchanged; both new jobs use the same `needs.changes.outputs.web == 'true'`, and the `has(...)` pattern at ci.yml:116 is untouched. On a non-web change the old required check reported 'skipped' and the new web-check reports 'success' ('no web change: rightly skipped'). Both satisfy branch protection and leave the run conclusion that deploy.yml:69 reads (workflow_run.conclusion == 'success') the same. This copies the existing jvm-analytics-check pattern. Stricter than before: if the changes job fails, the old web job was skipped (the required check passed as skipped); now web-check fails.
- Aggregator outcomes enumerated (ci.yml:786-800 plus the Python): all shards success leads to a count check, which passes only if expected+flaky+unexpected+skipped == the listed total and unexpected == skipped == 0. One shard failed: the matrix result is 'failure', so exit 1. A shard cancelled at its limit: 'cancelled', so exit 1. Build job failed: WEB_RESULT=failure (the shards are skipped), so exit 1. Web unchanged: web and shards both skipped, so exit 0. Web unchanged but anything ran: exit 1. Changes not success: exit 1. A whole-run cancel: always() still runs, sees a non-success result, exit 1. Missing report: `len(files) != 5`, so it fails. A skipped or fixme test: skipped > 0, so it fails. Missing or empty total: int() raises, so it fails. No path reports green with fewer than 372 tests run or with any shard not 'success'.
- Re-run of failed jobs: web-check depends on the shards, so it is re-run and re-reads needs.* from the new attempt. Re-run shards download `web-build-${run_id}`, which belongs to the same run and the same SHA (no other run's build; the download is scoped by --repo and the run id), and they replace their report via overwrite: true. A stale report can survive only if a re-run shard fails before uploading, and then the shard result is not success, so the check fails. Not tested empirically: no re-run attempt exists in the cited runs.
- web/e2e/national-shots.spec.ts:12 has a conditional test.skip ('goldens not recorded yet'). Before the lane such a skip would have passed the old job silently; now it fails web-check (skipped > 0). That is stricter, not looser, but a missing golden now turns the required check red.
- Retries: web/playwright.config.ts is unchanged (`retries: process.env.CI ? 1 : 0`, workers 1, fullyParallel false), so 'retries 1' was already 1. There is no job-level retry. No timeout was widened: the build job and the shards keep 30 minutes, the Chromium step keeps 14, and web-check is new at 10. No test was added to or removed from web/e2e; the only test edit is the Android one.
- Pinning: no new action. upload-artifact@043fb46d…(v7.0.1), checkout@3d3c42e5…, setup-node@82076278… and cache@55cc8345… are the same SHAs as before. Downloads use the preinstalled gh CLI.
- Permissions and secrets: the workflow default is contents: read (ci.yml:35). web-e2e and web-check add only `actions: read`, which `gh run download` needs to list and download artifacts; that is the minimum, and the download is scoped to `${{ github.run_id }}` in the same repository. The only credential these jobs get is github.token; no repository secret reaches web, web-e2e or web-check (none did before either).
- Consumers: tools/github-governance.ps1 is unchanged in the delta, and line 71 still requires 'Web (lint, types, tests, build, e2e)', which is now web-check's name. infra/tests/check_infra.py:921-944 exempts the build job and the matrix name and pins the shape; its Workflows tests pass on 1e4eb3bb (20 of 21 in my partial tree; the one error is a missing backend file, an artefact of exporting only .github, infra and tools). The artifact name changed from web-playwright-results to web-playwright-results-N; a grep of tools, .github, infra and scripts found no consumer.
- LiteMapScreen: the new trailing `imageDispatcher: CoroutineDispatcher = Dispatchers.IO` keeps production behaviour (IO). The previous last parameter is `focusId: String?`, not a lambda, so trailing-lambda syntax cannot break. Other callers (AmoTeamHosts.kt, PeripheryScreens.kt, MapFallbackListScreenshotTests.kt) do not pass it, so they keep IO. In the test, `waitUntil(10_000)` became `waitForIdle()` and the same SNAPSHOT-displayed and MAP-absent assertions remain, so no assertion is weakened. Not run locally (no Android build here); the Android job in run 44231175158 is green.

## shards-and-map-test verdict=pass
SUMMARY: Pass: no blocking findings, only lows.

**Scope.** The delta is f5bfee39..1e4eb3bb, plus a docs-only commit 25572e421 on top. Changed files: .github/workflows/ci.yml, web/scripts/ci.sh, infra/tests/check_infra.py, android/core-map/.../LiteMapScreen.kt, android/core-map/.../LiteMapScreenTest.kt, DECISIONS.md and docs/status/ci-web-e2e.md. Nothing changed outside what the lane described.

**The aggregator cannot go green early.** web-check (ci.yml:771-830) runs with always() and needs changes, web and web-e2e. It fails when the changes job did not succeed, which is stricter than before: the old job was then skipped, and a skipped job counts as passing. When the web area changed, both the build job and the matrix result must be success. Skipped, cancelled or failed results all fail the check. Never-started shards show up as skipped or cancelled, so they fail it too. The check also needs exactly 5 shard reports, 0 failed and 0 skipped tests, and a total equal to the build job's --list count. That count is not built from the build output, so a broken build cannot shorten it.

**The run evidence matches.** In run 44231175158 the shards ran 78, 72, 76, 72 and 74 tests, which is 372 of 372. In both runs the build job and all five shards succeeded. When the web area is unchanged, the shards are skipped exactly as the old job was. The changes filter and its condition are untouched.

**Playwright and the hard rules.** web/playwright.config.ts is not in the delta. retries stays at process.env.CI ? 1 : 0, so it was 1 before as well. workers is 1, fullyParallel is false and the reporters are the same. forbidOnly was absent before and is still absent. The expect timeout and webServer timeouts are unchanged. No timeout is widened: the web job keeps 30 minutes, the Playwright install keeps 14 minutes, the new shards have 30 minutes each and web-check has 10. There is no job-level retry. Every action is pinned by SHA, and no new action was added. Artifact downloads use the preinstalled gh against the same run_id.

**Shard isolation.** Each shard is its own runner, and its webServer entries start their own mock on 4010 and their own standalone server on 3100 (reuseExistingServer is false on CI). Each spec resets the mock. Screenshot baselines are unchanged.

**ci.sh.** The PW_SHARD passthrough is quoted correctly. The count is the sum of the --list JSON stats, and it gave 372.

**Consumers keep working.** The required name in tools/github-governance.ps1:71 is unchanged and now belongs to web-check. infra/tests/check_infra.py was updated. Its Workflows tests pass locally, apart from one error caused by a file my partial copy of the repository left out, which is unrelated. deploy.yml reads only the run conclusion. No tool consumes the old artifact name or the jobs list.

**LiteMapScreen.** The new parameter defaults to Dispatchers.IO, every production caller keeps that default, and the test's assertions are the same.

**What I could not check.** I could not run GitHub Actions. I did not see a failing-shard, cancelled-shard or skipped-shard run, so that path is checked from the code only. I did not run the Android unit test or the e2e suite, and I could not check the Compose threading claim on a device.

LOWS:
- Comment and step name overstate the flaky rule. .github/workflows/ci.yml:775 says web-check passes 'with 0 failed and 0 flaky', and the step at :806 is titled '(0 failed, 0 flaky, 0 skipped, ...)'. The code (:824-826) only prints a ::warning:: when tests are flaky, which is the same as before: the old web job also only warned and never failed on flaky. So the behaviour is unchanged and nothing was loosened. The wording should say that flaky warns and does not fail.
- The gate is now stricter on skipped tests, and this is not described. web-check fails when any test is skipped. Before, a skipped test passed. web/e2e/national-shots.spec.ts:12 skips itself when its goldens folder is missing. Today the goldens are recorded (run 44231175158 showed 0 skipped). If a later commit adds a shot spec before the web-snapshots workflow records its goldens, the required check will now go red where it used to go green. Stricter is acceptable, but the decision entry should say so.
- Count failures are swallowed, but the gate still fails safe. ci.yml:677 runs echo "total=$(bash scripts/ci.sh count-e2e)", so the command substitution's exit code is lost: ci.sh's set -euo pipefail does not reach the step. An empty total makes int('') raise in web-check, so the check fails. A shortened total, for example a spec that fails to load in --list, is also caught, because the shards hit the same load error and fail. Still, 'set -o pipefail; total=$(...); echo total=$total' would fail visibly in the build job itself.
- Pre-existing gap, not a regression. web/playwright.config.ts has no forbidOnly (none before, none after). A committed test.only would cut both the --list count and the shard runs, so 'ran == total' would still hold and the gate would pass with fewer tests. The old job had the same hole. The lane's claim that 'a lost test cannot pass' is therefore only true without .only. Recommend forbidOnly: !!process.env.CI.
- actions: read on web-e2e (ci.yml:702) and web-check (:784) is the minimum the artifacts REST API needs for gh run download. Both downloads are pinned to ${{ github.run_id }} (:721, :805), so they always read this run. No secrets are added. GH_TOKEN is github.token only, and the shards inherit the same top-level env as before. The gh CLI is the runner image's own version, not a pinned action. That is acceptable, but it is a moving tool.
- Stale artifacts across attempts cannot give a false green. The reports use overwrite: true, and web-check also requires needs.web-e2e.result == success, so a leftover report from an earlier attempt cannot stand in for a shard that did not succeed. The build artifact has a 1-day retention, so a 're-run failed jobs' on a shard after 24 hours fails closed. That is an inconvenience, not a breach.
- The failure artifact was renamed from web-playwright-results to web-playwright-results-<n> (ci.yml:765). No workflow, tool or script in the repository consumes either name, checked by git grep. The per-shard flaky step is kept (if: always(), same exit-0 behaviour as before), and the combined flaky warning is added in web-check.
- The LiteMapScreen unit test no longer exercises the real IO hop. The test now passes Dispatchers.Unconfined, so the production Dispatchers.IO path has no unit-test coverage under Compose. This is a small loss of coverage, not a weakened assertion: the test still asserts that SNAPSHOT is displayed and MAP does not exist. The 10-second waitUntil became waitForIdle, and assertIsDisplayed would still fail if the image never appeared. Production is unchanged: the default is IO at LiteMapScreen.kt:114, and every production caller relies on it (AmoTeamHosts.kt:266, PeripheryScreens.kt:129 and :226). The screenshot test MapFallbackListScreenshotTests.kt:53 does too. The state write after withContext resumes in produceState's composition effect context, which is the main thread on a device, so Unconfined does not hide a production threading bug. I could not verify this on a device.
- Commit trailers are cosmetic only. 49005d34c and ab0d93625 carry different Claude-Session URLs (…mnioLZHq… versus …mnioLvKP…), and 1e4eb3bb and 25572e421 have no Claude-Session line. DECISIONS.md is append-only: 0 lines removed, and D-CI-E2E-01 and -02 were added.
