## spoof verdict=pass
SUMMARY: Verdict: pass, no blocking findings. Read-only review of lane/android-integrity 791fefae..49e6abc6 (lane commits 17b145f32, faffe9d82, 2b8032659, 49e6abc6f). I ran nothing (no build, no tests) and nothing has been tried on a device. Every platform behaviour below is a platform assumption.

**What decides refusal:**
- HARD codes refuse the geo-validated action: MOCK_FLAG (SpoofSignals.kt:113), MOCK_APP_SELECTED (:106) and TEST_PROVIDER (:115). They are folded into isMock (FixManagerSource.kt:227), and the policy is forced to BLOCK_SALE (VisitPorts.kt:290, VisitFlow.kt:206, SrSaleKit.kt:291, AmoSaleKit.kt:226).
- Soft codes never block; they are stored in geo_fix.signals_json (VisitPorts.kt:58, BreadcrumbWiring.kt:46): test_provider_props, fake_gps_app_installed, gnss_no_sats, gnss_none, fix_stale, fix_clock_mismatch, jump, speed, provider_disagree, root_hint, emulator, hook_framework (SpoofSignals.kt:106-139).

**What each signal sees on Android 10-15 (platform assumptions):**
- MOCK_FLAG: the platform, and GMS for fused, sets isMock/isFromMockProvider on test-provider fixes. A non-root app cannot clear it.
- MOCK_APP_SELECTED: the AppOps read works only for packages the app can see, since QUERY_ALL_PACKAGES was removed. OEMs may refuse or misreport the read.
- getLastKnownLocation(NETWORK) is a passive read with no radio or battery cost. The cross-check is skipped when that fix is older than 2 minutes.
- All facts are cached for 10 minutes. There is no new sensor or request, so no battery budget breach.

**Attacks, as a rep without root:**
- Mock app selected, then Developer options hidden with settings put (the W1 path): REFUSED. Every fix still carries the mock flag, and MOCK_APP_SELECTED fires too if the app is listed. The gate also reads adb_wifi_enabled, so wireless debugging cannot be left on.
- A mock app that clears the mock flag: not possible without root or hooks on API 29+. With hooks (LSPatch, virtual container) it is FLAGGED soft (hook_framework, root_hint clone/foreign_data_dir), and Play Integrity is on the server.
- A joystick app using a test provider named "gps": REFUSED by the mock flag; test_provider_props is a soft flag on top.
- Replaying a stale real fix: not injectable without mock. Reused fixes are re-evaluated and keep the mock flag; fix_stale is soft.
- Location off after one good fix: LocationBlocked, with no reuse because access is checked before reuse.
- Airplane mode: no effect on GPS. The network cross-check is skipped, and a mock is still refused.
- Cloned app or work profile: FLAGGED soft (secondary_user, foreign_data_dir, clone_app_installed). Mocks from the personal profile still carry the mock flag.
- Time change: FLAGGED soft (fix_clock_mismatch, gps fixes only).

No practical non-root route passes a fake location as real with no refusal and no signal on the phone. The main gap is that soft signals are not uploaded yet (slice 3, contract 1.19.0), so the TSO and the server do not see them.

**False positives:**
- Indoors on a cheap phone (network-only, no satellites): ACCURACY_TOO_LOW or out of range leads to the existing Refresh and Force Sale with photo. No hard code fires.
- First fix after a reboot: the negative elapsed step is skipped.
- A legitimate jump after the phone was off: soft only.
- Emulator-like OEM build properties and gps provider properties: soft only.
- Bluetooth GPS (it uses mock locations) and an OEM that misreports AppOps: hard-refused with no override. These are low, but the Blocked text gives no next step. Recovery works: go back and re-tap starts a fresh visit uuid.

**Data:** signals_json holds only the code list, with no personal data. The previous fix (lat, lng) sits in a prefs file with backup off and no logging, but it is never cleared on logout. There is no change to UUIDs or payloads, and the Room 9 to 10 migration is additive with a test.

**Docs:** the docs are honest; nothing claims "cannot be spoofed". The decision text has small overstatements about attendance refusing and about refusing on a timeout. The residual-risk note should also name the no-root routes: LSPatch-style repackaging, virtual containers, and VMOS-type virtual ROMs.

**Not checked:**
- Anything on a device: OEM AppOps behaviour, the gps provider properties, GMS mock propagation, battery.
- Whether FixManager.take runs on the main thread.
- The server re-check code.
- CI results.

LOWS:
- Soft signals reach no one yet. geo_fix.signals_json (CaptureEntities.kt:54, written by VisitPorts.kt:58 and BreadcrumbWiring.kt:46) is local only, and RecordMapping does not send it (contract 1.19.0 is slice 3, per D-AINT-04). jump, speed, provider_disagree, gnss_*, fix_clock_mismatch, emulator and the new /proc/self/maps hook_framework (AndroidSpoofProbes.kt:95-99) are invisible to the TSO, the portal and the server re-check until then. Only the hard codes reach the server, folded into is_mock (FixManagerSource.kt:227), plus the older root_hints in device_status. A rep using LSPatch or a virtual container (VirtualXposed, VMOS) without host root gets soft flags at most, and those stay on the phone. So docs/05's 'report, don't just block' and CLAUDE.md's 'surface them' are not met yet. This should be carried as a named gap for slice 3, not as done.
- Folding hardSpoof into isMock (FixManagerSource.kt:227) changes what the uploaded GeoFix.is_mock means. For mock_app_selected or test_provider, the server stores is_mock=true even though the platform flag was false. The server cannot tell the platform mock flag from an inferred one until signals are sent. This needs a data-dictionary note.
- The comment at SpoofSignals.kt:105 ('a rep who selected a mock app is refused even on a timeout') is wrong. GeoVerdicts (shared/rules Geo.kt:154) checks fixOk before isMock, so a timeout with mock_app_selected gives NO_FIX and then Refresh/Force Sale. It is not a bypass: a force sale is photo-backed and never a clean geo sale (OpenVisit.cleanGeoSale). The comment or the rule should be fixed so they agree.
- D-AINT-04 says the fold makes 'every existing refusal site (attendance, ...)' refuse. AttendanceFlow.kt:136-157 does not refuse a mocked fix: it records the check-in with is_mock. That is the better behaviour (no outlet geofence, nobody trapped), but the decision text overstates it. TSO periphery fixes (TsoReadModels.kt:461) bypass FixManager, so only the raw mock flag applies there, not mock_app_selected or test_provider.
- A hard refusal has no 'what to do' text. VisitScreens.kt:386 shows out_blocked_mock ('This sale cannot be made because of a mock location' / Bangla equivalent) with only Go back. The rep can recover: go back and re-tap, since each open() mints a new visit uuid (VisitFlow.kt:157) and an abandoned close does not count as visited (Journey.kt:14). But nothing tells them to stop or uninstall the fake-GPS app. For mock_app_selected the fix itself may look fine, and clearing the selection needs Developer options on, which is gated. Reuse out_req_err_mock's 'turn it off and try again' wording and add the uninstall step, in Bangla and English.
- Hard false-positive risks rest on platform assumptions not checked on a device. (1) AppOps unsafeCheckOpNoThrow for another package's uid (AndroidSpoofProbes.kt:72-78): if an OEM returns MODE_ALLOWED for an installed but unselected listed app, the rep is hard-refused at every outlet with no force sale. It is on the walk list; consider soft until walked, as was done for test_provider_props. (2) Bluetooth or external GPS receivers feed Android through mock locations, so a legitimate user is hard-refused with no override. This is rare and consistent with D-OWNER-MDM-02, but it should be stated. (3) TEST_PROVIDER (SpoofSignals.kt:115) assumes GMS fused always reports 'fused' and the platform reports 'gps'/'network'. A null provider passes; an OEM-specific provider name would be hard-refused.
- Not refused, flagged softly, by design: a virtual container or clone (RootHints secondary_user / foreign_data_dir / clone_app_installed as ROOT_HINT), a work profile (secondary_user), an LSPatch-repackaged APK (XposedBridge class lookup gives HOOK_FRAMEWORK; Play Integrity on the server is the stronger signal), and a manual time change (FIX_CLOCK_MISMATCH on gps fixes only). The residual-risk paragraph in docs/status/android-integrity.md is honest but names only 'rooted phone / hooking framework that hides itself'. It should also name the no-root routes: LSPatch-style repackaging, VirtualApp-type containers, and VMOS-type guest-root virtual ROMs.
- Removing QUERY_ALL_PACKAGES narrows the existing FixDeviceState.mock_app_present and DEVICE_MOCK_APP_PRESENT server signal to the 16 listed packages plus RootHints' lists. Before, any non-system app requesting ACCESS_MOCK_LOCATION was reported. An unlisted fake-GPS app is now silent until it actually mocks a fix (it is then hard-refused by the mock flag). The status doc states this honestly. Several list entries (e.g. com.fakegps.mock, com.pro.fakegps, com.mocklocation.fakegps) look unverified or invented. The KDoc of MockAppScanner (AndroidDeviceState.kt:12-14) is updated, but the probe class comment at AndroidSpoofProbes.kt:52-55 should keep saying the scan only sees declared packages.
- AndroidSpoofProbes KDoc (lines 27-28) says the 'gps' provider properties are read per fix, but they are inside the 10-minute cached facts() (line 63). Also, facts() runs inside FixManager.build on the caller's dispatcher: up to 16 getPackageInfo calls, a MockAppScanner run, RootHints file and mount reads, and up to 20k lines of /proc/self/maps every 10 minutes. I did not check the dispatcher. If take() runs on Main, this is possible jank on 2 GB phones. It is not a battery breach: no request and no sensor.
- PrefsPreviousFixStore (PreviousFixStore.kt:17-26) keeps the last fresh fix (lat, lng, elapsed) in a new prefs file. It is never cleared on logout, so on a shared phone the next rep's first fix is compared with the previous rep's position (soft jump/speed noise), and the previous rep's last position stays on the phone. Backup is off in all three manifests, and nothing is logged. Clear it on logout or day close. elapsedMs compared across a reboot only skips when the new value is smaller, so a reboot can give a wrong dt; that yields only soft speed or jump codes.
- docs/05 (line 28) still says to keep a 'configurable hard-block'. The phone now forces BLOCK_SALE regardless of cfg.geo.mock_policy (VisitPorts.kt:290). That is justified by the owner directive, but docs/05 and the bundle/admin portal description of mock_policy should say the phone ignores warn_rep and silent_flag.
- Test changes match what was stated. FixModelContractTest got exactly one per-file allowance (AndroidSpoofProbes.kt: getLastKnownLocation), the stated single allowance. VisitFlowTest.mockedFixIsNeverValid was inverted to the new owner rule and three tests were added: bundle cannot soften, non-flag hard code, soft never blocks. The RecordPayloadContractTest serverSet change comes from the train merge (sr-server B5), not this lane. Room 9 to 10 is an additive nullable column (AutoMigration plus Migration910Test). It changes no payload or UUID; signals are not in the record mapping.

## gate-foldin verdict=pass
SUMMARY: I found no blocking issue in lane commits 17b145f3..49e6abc6, which is the part of 791fefae..49e6abc6 not brought in by the integration merge 1c9b26a52. Nothing ran on a device or in CI, and I did not run Gradle. A rep without root has no practical way to save a visit or sale on a fake location without a refusal or a signal. With Developer options off, a mock provider's fixes carry the platform mock flag (not verified on a device), and that flag now refuses the visit whatever the bundle says. A virtual-space clone is caught as root hints through the existing device status. The fold-in items are present and their tests would fail without the fixes: wireless debugging as a third flag on API 30+, TsoOutbox.enqueueAll and resolveTask gated, recordMediaMeta open, the gate installed in all three Application.onCreate, Sync now on the gate screen, and the atomic files and release flag. GateClosedException is a cancellation, so it does not crash, and the callers I sampled rethrow it and reset their busy state. The benchmark build gets its own application id and release still runs the Google services task. The Room 9 to 10 auto migration only adds a column; it keeps data, the schema file matches, the migration test is real, and queued payloads and UUIDs do not change. The only new location call is one passive last-known network read in the one allowed file; there is no new location request, listener or periodic work. Most important lows: (L1) the gate's recents code clears the secure-screen flag below API 33, so the TSO's device codes or an OTP can become screenshottable after the gate lifts. (L2) Removing QUERY_ALL_PACKAGES narrows the device-owner release fallback that un-suspends other apps, and the mock-app signals. (L3) No test covers the wiring that turns a selected mock app or test provider into a mocked fix. (L14) The soft spoof signals stay on the phone until contract 1.19.0. D-AINT-05 does not list low 10, so I could not verify it.
