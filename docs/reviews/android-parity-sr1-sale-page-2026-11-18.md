## behaviour verdict=fail
SUMMARY: The Sale-page slices are presentation only on the money side. The only blocking finding is that the AMO out-of-range step is restyled, which the handover says does not happen.

**What I checked and found clean:**
- **Quantities and money:** QuantityPopup keeps the same logic (MaxLineQty, the stepper, onSave(value), quick steps, stats still read only when the unit matches). Only the tint, close button, underline, stats gradient and widths changed.
- **Partial payment:** the new SR CreditDialog uses the same parse and bound as CreditPrompt (PaidInput.parse, amount below netMtk, Yes enabled only when valid), the same vm.setPaid(parsed), and null on 'na'. SaleRoute still goes Credit to Review.
- **Memo, stock check and gates:** nothing touched the stock check, prerequisite gates, memo builder, printing payload, Room, sync or geofence verdict logic. The geofence code is only re-laid-out, with the same verdicts, the same refresh and force conditions, and the same ForceSale confirm path.
- **Merge dcdcbd87 in SaleScreens.kt:** against the integration parent (951292a48) the file differs by only the two lane lines (softCorners on RetailerPickerField, and manual on the zero-sale confirm). The headerCard branch, the AMO header work and the amoSkuCard path are all kept; nothing was dropped.
- **Overload clash:** the integration branch's private CreditDialog (8 args, AMO) and the lane's new public CreditDialog (review, onPaid, onCancel) are distinct overloads, and the private one is not visible from SaleRoute. The 30047fd5 fix only removes a duplicate RoundedCornerShape import.
- **AMO/TSO sale screens:** SaleRoute's creditAsDialog path and the AMO's own sale hosts are unchanged. New options (manual, softCorners, quantityPopup, AronManualDialog) default off, and the SR hosts turn them on. SaveAndPrintDialogs defaults manual to false.
- **Tests and goldens:** only additions. QuantityPopupContrastTest, DarkButtonContrastTest, SrParity1bSaleTests and 35 new srp1b_* PNGs were added. No test file was deleted or edited, and no existing PNG changed, so no amo_ or tso_ golden changed.

**What I could not verify:** nothing was built or run. I did not confirm that the existing Robolectric and Roborazzi tests still pass, did not walk any device, and did not compare against the owner's screenshots.

### BLOCKING: AMO out-of-range (control call) screen is restyled and loses its bottom bar; handover says AMO/TSO are untouched
WHERE: android/feature-outlet/.../VisitScreens.kt (VisitCheckContent, geoPanel branch, SrOutOfRangeButtons, 'is NeedsDecision -> if (!geoPanel)'); AMO caller android/app-amo/.../ControlCallHost.kt:164 passes geoPanel = true
WHY: The SR look was put under the geoPanel flag, but the AMO control-call host also sets geoPanel = true. On an AMO phone the out-of-range step now draws the red triangle, centred sentence and page buttons, and the Force Sale / Refresh bar is no longer drawn (the AMO's Manual Override label becomes a page-level gradient button). The lane's handover says 'new core-ui options are default-off so AMO/TSO stay 0 changed' and no amo_ golden covers this step, so the change is neither recorded nor caught. The force/refresh conditions themselves are preserved (force when forceSaleAvailable, refresh when refreshLeft and the verdict is not NO_OUTLET_LOCATION), so no money, sync or geofence rule changes, but it is an unintended, unreviewed AMO UI change that breaks the lane's own stated acceptance.
SCENARIO: AMO opens a control call at an outlet 163 m away: before, the verdict card plus a bottom bar with Refresh (and Manual Override as secondary); after, the SR-style warning page with buttons inside the scrolling page and no bar. Fix: gate the SR layout on a new SR-only flag (for example callQuestion != null or a dedicated parameter), or record and have the lead accept AMO goldens.

LOWS:
- Behaviour change on the SR out-of-range page: for verdict NO_OUTLET_LOCATION with forceSaleAvailable false, nothing is offered now. Before, the bar showed a refresh or a disabled refresh with the reason 'no refresh left'. Neither moved the visit on, but the rep sees an empty page with only the back/no-sale links.
- Dialog dismissal changed in the SR save/print boxes: Info and Done boxes (SaveFailed, LimitReached, TooLong, Done) now go through AronManualDialog with the default no-op onDismiss. Before, AlertDialog used onDismissRequest = ok, so back or tap-outside acted as OK. Now only the OK button proceeds (for Done, onFinished fires only on OK). The Yes/No boxes keep dismiss disabled as before. Presentation-adjacent and the OK button works, but it is a behaviour change the handover does not mention.
- The partial-payment CreditDialog for SR sets dismissOnBackPress = false and dismissOnClickOutside = false, so Back on that box does nothing. The old full-screen CreditPrompt followed the host's back handling, which I did not trace. Pressing 'na' still clears paid and returns to Review. The credit rules are the same (PaidInput.parse, amount below net, Yes disabled until valid, same setPaid).
- The unchanged handover line says every existing golden is unchanged, and the diff confirms no existing PNG was modified or removed (only new srp1b_* files). However, existing tests that run changed code (VisitGeoTest with geoPanel = true, ManualCallStartTest, VisitScreensTest, AmoControlCallHostTest, ScreenshotTests line 309) were not modified, and I could not run them, so I cannot confirm they still pass after the VisitCheckContent restructure.

## ui verdict=pass
SUMMARY: I found no blocking UI defect in the Sale-page slices on origin/lane/android-parity-sr-1 (30047fd5), reading the code only. Every string is in the Bangla and English resource files. Key figures use dark ink on solid or gradient panels with a 7:1 test (QuantityPopupContrastTest, DarkButtonContrastTest). Interactive items keep their descriptions: the close cross has a description and a 48 dp hit area, and the credit field has a description. The out-of-range, force-reason, call-question and permission screens keep their error, no-refresh and reading-fix states. The packshot path is not changed in this diff. The lows are a Sunlight patch behind the credit label, no scroll or font-2.0 golden for the credit box, a possible dead-end out-of-range page, an un-restyled print-failed dialog, untested contrast of small text on the lavender tint, and a possible double TalkBack reading of the credit label. Nothing was built or run, and I did not open the goldens.
