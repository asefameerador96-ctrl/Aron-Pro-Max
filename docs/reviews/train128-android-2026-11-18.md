## prog-chain — PASS

PASS. I checked by reading only; I did not run Gradle. The delta (d6ab7faef against 0baf2b4dda) changes only the fallback with no recorded order in delta() and in unknownOrder(). The merged head 2918099a9c has the same feature-programmes files as d6ab7faef.

**Full rule (order known): unchanged.** Neither the add/subtract code nor the uuid-set logic is in the diff.

**Fallback: no new double count.** The edit branch now needs every memo of the chain, down to the root, to be dated after T. That implies the old test (the edit and its direct parent dated after T), so the new add set is contained in the old one.
- It also closes an old double-count risk: an ancestor missing from the phone (a missing, b and c dated after T) used to add c, and now returns null and leaves c out.

**Cases enumerated by hand** (> T means dated after through_date T; <= T means dated up to and including T):
- **a<-b**
  - a<=T, b>T: adds nothing; unknownOrder = 2 (a may be in the figure, b is the edit).
  - a>T, b>T: adds b; a is in replaced; unknownOrder = 0.
  - a>T, b<=T: adds nothing; a is excluded as "counted by its edit"; unknownOrder = 1.
  - both <=T: adds nothing; unknownOrder = 2.
- **a<-b<-c**
  - all >T: adds c only; unknownOrder = 0.
  - root <=T, rest >T: adds nothing; unknownOrder = 2 (a and c; b is counted by its edit).
  - a>T, b<=T, c>T: adds nothing; unknownOrder = 2 (b and c).
  - a>T, b>T, c<=T: adds nothing; unknownOrder = 1 (c).
  - a<=T, b<=T, c>T: unknownOrder = 3.
  - all <=T: unknownOrder = 3.
- **a<-b<-c<-d** generalises the same way: all >T adds d and gives 0; root <=T, rest >T gives 2.
- **Acked or pending versions:** the state matters only for the root branch and for whether a memo is live. A pending root dated up to T is never counted in the note.
- **Missing ancestor:** nothing is added and the edit is counted once.
- **Loop:** nothing is added and the note counts 0 (a theoretical case).
- **Voided tip:** nothing is added, which is correct; the note says 1 where 0 would be exact (a low).
- **Fork:** both edits are added. This was already true before this change and is in the lows.

In none of these cases does a single memo, or two versions of one chain, get added twice. The new tests only add assertions; none were weakened or deleted. chainOf costs O(n * 65), not quadratic.
