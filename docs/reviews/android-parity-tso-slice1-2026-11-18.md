## tso-slice1 verdict=pass
SUMMARY: TSO slice 1 (bfea7197) passes with no blocking defects, reviewed by reading the lane-only diff from merge-base 951292a48. - The clear icon is inert. It shows a red trash glyph on any route that has data and does nothing when tapped. It also carries a 'Clear this route' content description but no button role when onClear is null, so TalkBack announces an action that does not exist. No function is lost, because clear never existed in this build. It is recorded as D-PAR-TSO-03 plus request row 1. A sighted TSO may still tap it and wonder why nothing happens. Consider hiding the semantics label until the host wires the action.

The lane's own status doc says a manual or owner ruling overrides a screenshot (KEEP). D-PAR-TSO-04 does not say it supersedes D-TSO-MAN-51, and the KDoc of FinalSubmitScreen still describes the 'not due' line. The rep now only learns about not-uploaded routes after tapping Submit. Add the supersession note and fix the stale KDoc. FsRoute.notDue is now unused by the UI.

QueryModel.retailer still parses bool criteria from older or other rubrics, so those questions are silently never asked and never answered. Answers are optional per D-199, so nothing blocks. The questions are forced to Bangla (labelBn ?: labelEn) even in English mode, as screenshot 37 shows. This is recorded, but it is a small data-collection reduction.
- The deleted golden tso_visit_query_bn.png was a normal two-question view with a Yes answer. Its only successor is tso_visit_query_3line_bn, a long-label stress case. No ordinary-width Visit query golden remains, and the Final Submit screenshot tests now use the cascade only (loadCascade, pickLevel), so the flat-zone path has no golden (code tests still cover it). No test was skipped or loosened. The not-due and not-uploaded tests were inverted to assert absence, which matches D-PAR-TSO-04. Add one plain Visit query golden back.
- On the online map (live = online and Maps key present) My Team loses its Refresh button and 'as of' line. Retailer loses its refresh button, count caption and the 'computed on phone' / 'cached' banners (D-PAR-TSO-07). While online, a rep on My Team cannot re-read the last fixes without leaving the screen or changing zone. On Retailer, a result that fell back to a phone-computed or cached list shows no warning. My Team keeps its cached banner. This is recorded and follows screenshots 28 and 29, but it reduces staleness honesty.
- Fullscreen map edge case. full is saved across recreation. If the network drops while fullscreen, live goes false and the fullscreen and recentre buttons disappear. The zone picker is already hidden, so only the system Back (a BackHandler is installed) leaves fullscreen. Recentre works by re-creating the map composable (key(recentred)). That is not continuous GPS and no location layer is enabled, which matches D-PAR-TSO-06. I could not verify the camera actually re-frames the points.
- The no-network list is still drawn offline, because LiteMapScreen and the list path are unchanged and the extras only hide when live. Offline behaviour is preserved by reading the code, not by running it.
- Settings is now a plain drawer row above Log Out (TsoDrawer entries, with tests TsoShellTest, TsoNavigationTest and TsoAppTest updated). Log Out is still reachable. The drawer no longer shows the user's full name; the top-bar greeting still does. The string tso_drawer_role is probably now unused in both locales (one grep hit per locale file, no code use), which may trip an unused-resource lint.
- Contrast and tokens. The clear icon uses hardcoded colours: 0xFFC62828 on light and 0xFFFF6B6B on dark or solid. These are fine as icon contrast (roughly 5:1 or better, estimated, not computed) but are not design tokens, which sits against the rule 14 'contrast computed from tokens' line. The map buttons use look.card and look.ink. The disabled dropdown placeholders use haloWhenDisabled, and I could not check their contrast. No key figures were changed in this slice.
- Strings are all in resources, with EN and BN given for the new ones (tso_fs_clear_route and three map strings). The Bangla reads correctly to me. The tso_fs_not_due and tso_fs_not_uploaded strings are removed in both locales with no remaining references in the repo at bfea7197.
