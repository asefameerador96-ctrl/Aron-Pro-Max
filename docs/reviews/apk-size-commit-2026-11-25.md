## okhttp-psl: PASS

How it is excluded: android/app-{sr,amo,tso}/build.gradle.kts add androidResources { ignoreAssetsPatterns += "!PublicSuffixDatabase.list" }. In aapt syntax a leading '!' means 'ignore silently', not 'keep'. The phone HTTP client is OkHttp 5.5.0 (gradle/libs.versions.toml line 53, via okhttp-bom in core-network). In OkHttp the public suffix list is read only by HttpUrl.topPrivateDomain() and by Cookie.parse's public-suffix check on Domain attributes. Cookie.parse is reached only through a CookieJar other than NO_COOKIES. CertificatePinner, OkHostnameVerifier and HttpUrl parsing/IDN (toHttpUrlOrNull) do not read it. If the asset is missing, the load fails lazily on first use: an IOException is logged, then getEffectiveTldPlusOne throws IllegalStateException. Nothing reads the list at startup.

Evidence from git grep at aa138d2d02 over android/: no topPrivateDomain, CookieJar, JavaNetCookieJar, Cookie.parse, okhttp3.Cookie, getEffectiveTldPlusOne, CertificatePinner or hostnameVerifier. All phone OkHttpClients have no cookieJar, so the default NO_COOKIES applies: AronApiClient.defaultOkHttp() and its newBuilder copies, MediaHttpApi.blobClient, and the AV clients in */SessionModule.kt. HttpUrl use is limited to toHttpUrlOrNull, isHttps, host and newBuilder (ApiOrigin, MediaHttpApi, SupportUpload, ApkDownloader), none of which reads the list. TLS policy is network_security_config.xml (HTTPS only, system CAs, no pinning, enforced by the platform), so nothing in security behaviour changes. No Ktor client, Coil, Glide or Retrofit is on the phone, and Firebase, Play Integrity, Maps and play-services-location do not use OkHttp's list.

Conclusion: no reachable crash path and no change to security behaviour, so nothing is blocking. Remaining risk is latent: a future CookieJar or topPrivateDomain call would crash at runtime, and no test or runtime guard covers that today. Smaller points: the lane note's 'only topPrivateDomain' wording is incomplete, the absence of the asset is not checked by any gate, and the += may have replaced aapt's default ignore-assets list. Not verifiable here: OkHttp 5.5.0 internals (not in the repo) and transitive AAR behaviour. Lows:
- Lane note docs/status/apk-size-2026-11-18.md (line 115) says OkHttp 5.5.0 reads the list 'only through HttpUrl.topPrivateDomain()'. That is incomplete. Cookie.parse also calls PublicSuffixDatabase.getEffectiveTldPlusOne when a Set-Cookie carries a Domain attribute different from the host. Cookie.parse only runs when a CookieJar other than NO_COOKIES is installed, which is why the conclusion still holds. The build-file comment does name both conditions. The note should be corrected.
- No guard or test keeps the precondition true. Nothing in the repo stops a later change from adding .cookieJar(...) / JavaNetCookieJar or calling topPrivateDomain(). Upstream behaviour, recalled from OkHttp source and not checked against the 5.5.0 artifact here: assets.open throws an IOException, which is caught and logged, and getEffectiveTldPlusOne then throws IllegalStateException('Unable to load ... resource'). This happens lazily on first use, not at startup. With a jar, it would happen inside the call on the first Set-Cookie with a Domain attribute. AronApiClient.classify only handles IOException, so it would surface as an uncaught crash. Suggestion: a unit test that asserts every phone OkHttpClient (AronApiClient.defaultOkHttp(), the AV clients in */SessionModule.kt, MediaHttpApi.blobClient) has cookieJar == CookieJar.NO_COOKIES, or a grep check in CI for topPrivateDomain/CookieJar under android/**/src/main.
- Packaging side effect to check: androidResources.ignoreAssetsPatterns starts empty, so '+= "!PublicSuffixDatabase.list"' makes the list exactly that one pattern. That probably replaces aapt's default ignore list ('!.svn:!.git:!.ds_store:!*.scc:.*:<dir>_*:!CVS:!thumbs.db:!picasa.ini:!*~'). If so, hidden files and underscore-prefixed asset folders from libraries would now be packaged. This affects size or contents, not security. Diff the release APK asset listing before and after, or append the default patterns explicitly.
- That the asset is absent from the APK was checked by hand by the lane ('confirmed absent from the APK'). No size or APK-content gate asserts it, and nothing asserts that no other asset was dropped. The benchmark and benchmarkProfile build types inherit the setting, which is fine.
- Not knowable from source alone: (1) OkHttp 5.5.0 internals (the asset name PublicSuffixDatabase.list, the AssetPublicSuffixList loader via the androidx-startup context, and the throw-on-missing behaviour) come from upstream knowledge and are not in the repo. (2) Whether some transitive AAR calls topPrivateDomain or installs a jar on its own OkHttpClient. Evidence makes this unlikely: the phone dependencies in gradle/libs.versions.toml (firebase-messaging, play integrity, play-services-location, maps-compose, CameraX, Room, WorkManager, Hilt, argon2kt, sqlcipher) do not use OkHttp's PSL, and there is no Coil, Glide, Retrofit or Ktor client on the phone. (3) R8 does not strip or add assets, so it does not change this.
