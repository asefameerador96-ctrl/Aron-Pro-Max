## closed-by-validation verdict=pass
SUMMARY: Pass: no blocking defect found. I read the code only; nothing was built or run, so every test claim below is from reading the test source.

**Item 4, closed_by check (IngestService.closedByProblem, called in process() right after the shape check):**
- **(a) Absent member:** the first line returns null when the type is not attendance_event or `"closed_by" !in payload`, so old phones, rep check-outs and every check-in pass exactly as before. Train-118 phones do not write a JSON null: RecordMapping.json on origin/lane/android-gates is `Json { encodeDefaults = false; explicitNulls = true }`, the DTO member is `closedBy: String? = null`, and RecordMapping.attendance sets it to "phone" or null, so a null equals the default and is left out. A JSON null from any other sender is refused as schema_invalid; that is unchanged, because the column is NOT NULL (V0201) and the insert already failed with 23502, which maps to schema_invalid.
- **(b) Values:** "phone" on a check_out and "rep" on either kind are accepted. "phone" on a check_in, another text, a number or null get a final schema_invalid through finalReject (retryable = false), the same code and flag the database CHECK path gave, so phones do not loop. A resend of such a record gets schema_invalid again (sync_rejected upsert, registry untouched).
- **(c) Before any write:** the check runs before the registry lock, the window check and RecordWriter; only the usual reject bookkeeping (sync_rejected, registry "rejected") is written. The detail texts are fixed strings plus at most 20 characters of the sent value.
- **(d) Duplicate ordering:** unchanged for valid records, since the code check passes and the unique indexes answer attendance_duplicate as before. For invalid values the CHECK already fired before the unique index.

**Item 5, routeCapturesExist and the worker late raise:** both now skip registry rows flagged manual_entry. That flag is set in one place only (IngestService line 1317, when ctx.manual != null, i.e. the web ingestManual by SUPPORT/ADMIN/SUPERADMIN). A phone record cannot carry it: flags are not in the envelope, and register() merges flags only on the same client_uuid and hash. A real phone capture on the same day has its own registry row without the flag and still counts; CheckoutClosedByTest covers that. routeCapturesExist has one production caller (checkoutWithoutSubmit, line 866); no automatic-submit logic uses it. `coalesce(flags, '{}')` handles a null flags column.

**(f) V0240:** one `COMMENT ON COLUMN` with `lock_timeout 5s`. It is metadata only, takes a lock that does not block reads or writes, and is forward-only. V0201, V0202 and V0203 are byte-identical to 39db6c734.

**(g) Contract:** the openapi.yaml, slice and openapi.d.ts diffs change the description of AttendanceClosedBy only; the enum and schema are untouched and the version stays 1.19.0. The WireDtos change is one comment line, now emitted from the generator's MEMBER_DOCS; the other three entries match comments already in the file.
