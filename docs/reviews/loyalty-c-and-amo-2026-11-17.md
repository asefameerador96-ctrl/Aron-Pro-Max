### BLOCKING upheld=3/3: C-R4 closes a released child that comes back parent_missing as 'discarded'. Phones treat that as a final rejection and never send the record again, so the record is lost.
WHERE: backend/sync/src/main/kotlin/com/aktcl/aron/backend/sync/IngestService.kt:527-529 (settleChild, the PARENT_MISSING branch, new in 5840376f2). Phone side: android/core-sync/src/main/kotlin/com/aktcl/aron/core/sync/SyncRules.kt:63-66 and SyncEngine.kt:461-465. Contract: contract/openapi.yaml:9645, where Resolution.resolution is limited to [accepted, accepted_with_fix, discarded].
WHY: The server's comment says the item is closed as a 'return to the device' so that 'the phone's resend is processed normally, the ordinary parent_missing retry path'. But the phone never learns the note. resolutionsAfter() / resolutions() send only status='discarded', and AckRules.resolution("discarded") moves the outbox row to OutboxState.REJECTED, which is final. No phone code re-sends a REJECTED row. So the server writes the registry row as 'parked' and closes the item, and the phone drops the record. Nothing is stored, nothing is re-sent, the device and server counts no longer reconcile, and the reviewer has no open item left to act on. Before this change (a697bb458) such a child stayed open for its own review. The branch is generic: it is not limited to gift_photo. It fires for any held child with a second parent: due_collection (against_memo_client_uuid + visit_client_uuid), qc_line (visit + memo), call_assessment (visit + visit_plan_outlet), and gift_photo whose redemption line is missing. The new test acceptingAHeaderWhileALineHasNotSyncedYieldsThePhotoToTheOrdinaryRetryPath (GiftPhotoRecordsTest) passes only because it re-sends the photo by hand from the server-side test harness. A real phone would not re-send it. The C-R4 re-open path for returned records (returnedWithoutOpenItem, plus the ON CONFLICT re-open in quarantine(), IngestService.kt:1782-1790) depends on the same resend that phones never make.
SCENARIO: 1) SR collects dues today at visit V, against old memo M. M is quarantined (for example business_date_out_of_window). V is parked or not uploaded yet. 2) due_collection D arrives and is held with M ('parent M is quarantined'); the phone marks D QUARANTINED. 3) A reviewer accepts M. The release of D returns parent_missing (V is missing), and settleChild closes D's item as status='discarded', note 'return_to_device: ...'. 4) The next sync or bundle delivers Resolution{D, resolution:'discarded'}; the phone sets D to REJECTED/'discarded'. 5) V syncs later, but D is never sent again. The cash collection is missing from the server and the dues stay open. The gift flavour of the same bug: the photo of a redemption whose second line has not synced is lost the same way after the header is accepted. Fix options: keep the item open (the old STAYS behaviour), or add a resolution value the phone treats as retryable. The second needs a contract change and phone work, and can only be added as a new enum value, which 1.16.0 phones ignore.
