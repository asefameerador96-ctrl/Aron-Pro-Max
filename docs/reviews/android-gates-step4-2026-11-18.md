## day-path-t1-t2 verdict=fail
SUMMARY: Verdict: fail, on one blocking point. I read the code of lane/android-gates b680476e (delta 12a178bc..b680476e) against D-LEAD-PREREQ-02/03/04 and the step-3 review. Nothing was built, run or walked on a device.

T1 is fixed on SR and AMO. resumeDay runs dropStaleEdit before the day close, and it only touches a draft with edit != null, committed == null and a date earlier than today. A same-day edit is untouched. Saving and dropping are serialised by SaleFlow.lock, and a committed edit or saved memo is never dropped. After the drop openWorkNow is null, so the day closes and the gate follows today (test anUnsavedMemoEditAcrossMidnightIsDroppedAndTheDayCloses). Gaps: the editDropped notice is not rebuilt after a kill, and it is set even when nothing was dropped.

T2, the automatic path, is fixed. The AMO end goes through closeVisit() under closeLock, exactly the rep's path. The SR end goes through closeVisitByPhone, giving sold, zero_sale_stock_ok or abandoned; that matches the sale screen's close and the back press for each kind of content I read: memo with lines, zero-sale or QC memo, survey only, nothing. The close is dated with the visit's date. A failing close is caught, the draft is kept until the close is stored, and the next start or resume retries it with no crash loop. A kill between the close and the day submit is resumed once.

Blocking: on SR the rep's own guided way out, the gate's 'Close the open call' (SrApp.kt:379), plus the back press of a restored call, still writes 'abandoned' / is_zero_sale=true for a call with a saved sale. The AMO button classifies; the SR one does not. This was already in the code before this step, but it is the T2 defect still reachable on SR.

Mutex: one Mutex per day object covers every resumeDay caller (start, ON_RESUME, the midnight and 04:00 timer, call ended). I found no deadlock with closeLock, SaleFlow.lock or a check-out. The location attempt sits inside the lock, so later callers wait up to the fix limit. The 04:00 boundary is added on SR and AMO. The start no longer waits on resumeDay, and the gate starts fail-closed at NOT_CHECKED_IN. But Attendance is restored only at the end, so a D+1 check-in can be pressed during a forgotten day's location attempt; this is new on AMO, and I found no data harm.

The rollover notice is rebuilt after a kill, but it also wrongly says 'the phone ended it' after a legitimate manual close past midnight.

Not checked: runtime timing of the races, FixManager ordering, the server's handling of two closes beyond the earlier review, T3 to T5 (other lenses), and the AMO edit screen's behaviour after a drop.

### BLOCKING upheld=3/3: T5 is still open for memo prints (rank 3) and AMO rank-2 records: the rank fallback still withholds Send again because of a refused sibling
