# android-sys: the support public key for PDA to Support (for the lead, backend-admin, infra)

F-SYS-021 encrypts the support file on the phone to the AKTCL support public key (docs/17 s10.4, contract
`createSupportUpload`: "The zip is encrypted on the phone with the support public key"; key custody docs/21 s5, OI-17-11).
No config key carries that public key yet, so the phone shows "not set up on this phone yet" and sends nothing.

Needed:
1. A key pair generated by the owner's side (infra script; the private key goes to Key Vault, never to git or a phone).
   RSA 3072 (or 2048) is what the phone uses: RSA-OAEP with SHA-256 wraps a per-file AES-256-GCM key.
2. The public key delivered to phones, either:
   - a config key `cfg.support.public_key_spki` (string, base64 X.509 SubjectPublicKeyInfo, scope G, risk C2), in the
     docs/24 s9.5 registry and the bundle's config section; or
   - a build-time constant from a GitHub secret (less flexible: rotation needs a release).
   The phone reads it through `SupportController(supportPublicKey = { reference.config("cfg.support.public_key_spki", now) })`.
3. A desk tool that opens a file: layout "ARONSUP1" | u16 wrapped-key length | RSA-OAEP(SHA-256, MGF1 SHA-256) wrapped
   AES key | 12-byte IV | AES-GCM ciphertext+tag; plaintext is gzip(JSON), see `SupportBundle` (core-system).
