## R-PAR-SR1-01: online address on Attendance (display only)
The reference shows a reverse-geocoded address ("Kamal Ataturk Avenue, Banani, ...") on the Attendance location card; ours shows coordinates and accuracy (offline-first, UI-SR-11). If the owner wants the address text, it needs a server or Maps reverse-geocode call made only while online, cached with the fix and never in the check-in path. A behaviour and contract change, so not built in this lane.


## R-PAR-SR1-02: ADS (and the stored `outlet_sku_stats`) for the quantity pop-up
**What the old pop-up shows (manual 22, `docs/ui-reference/sr/manual/22-enter_quantity.md`):** an amber panel with three rows: আগের দিন (the outlet's quantity of this SKU on its previous selling day), ADS (average daily sales, "3.33" in the example) and SDLW (same day last week). The manual does not state the ADS period. The server already defines it: contract 1.16.0 (`docs/requests/contract-1.15-sr-server-train2.md`, D-SV2-05): ADS = the SKU's sale quantity in the 30 calendar days before the bundle date x 100 / the elapsed calendar days of that window (the days since the outlet's first selling memo when younger), rounded half up, in base units; owner question still open there (per calendar day vs per selling day).
**Where we stand:** the SERVER side exists (`Bundle.outlet_sku_stats`, positional `[sku_delta, prev, ads, sdlw]` per outlet, in `contract/openapi.yaml` and `backend/sync/BundleService.kt`). The ANDROID side does not read it: no DTO, no table or cache column, no repository method; `kit.skuStats` in `SrSaleHosts.kt` builds আগের দিন and SDLW only from the outlet's sales already on the phone and passes `adsHundredthsOf = { null }`, so ADS shows N/A. (This corrects D-PAR-SR1-12, which said no source exists on INT: the source is the server bundle, not yet consumed by the app.)
**What a lane needs to do (data layer, not a look change):** parse `outlet_sku_stats` in the bundle and delta apply (whole-section replace, `outlet_sku_stats_truncated`), store it per outlet and SKU, convert base units to the entry unit with `pack_factor` (packets / dozens / box of 25, rule 5), and feed `SkuStatsBuilder.build(..., adsHundredthsOf = ...)` and prefer the server's `prev` / `sdlw` over the phone's own window when present. Per outlet and SKU the bundle already carries `prev`, `ads` (hundredths of a base unit per day) and `sdlw`. The pop-up needs no further change: `SkuStats.adsHundredths` is displayed as is.
